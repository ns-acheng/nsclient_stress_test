# Service Stress Test & Resource Monitor

This tool is designed to perform stress testing, resource monitoring, and stability checks on the Netskope Client (`stAgentSvc`) and Driver (`stadrv`) within a Windows/MacOS environment. It simulates user activity (web browsing, network requests) while cycling service states and monitoring for crashes.

## Prerequisites

* **Operating System:**
  * **Windows:** Windows 10, Windows 11, or Windows Server (64-bit recommended).
  * **MacOS:** macOS 12 Monterey or newer (Intel/Apple Silicon).
* **Python:** Python 3.10 or higher.
* **Permissions:** **Administrator / Root privileges** are strictly required to control services and access system debug privileges.

## Installation

1.  Ensure Python is added to your system PATH.
2.  Install the required dependencies using the provided requirements file:

```cmd
pip install -r requirement.txt
```



## Run the Tool

### Configuration
Before testing, enable correct feature to test. See [configuration.md](configuration.md).

`data/config.json` supports `decouple_client` for traffic-only runs:

- `decouple_client: 0` (default): normal behavior.
- `decouple_client: 1`: traffic generation only mode.

When `decouple_client` is `1`, the tool skips all client-related actions:

- no service or driver start/stop/restart actions
- no client status/file/service checks
- no `nsconfig.json` checks or updates
- no `client_feature_toggling` actions (including WebUI login)
- no system hosts file backup/modify/restore actions

Only `traffic_gen` actions run in this mode.

### Windows
1. Open a terminal as **Administrator**.
2. Run the main entry point:
   ```cmd
   python main.py
   ```

### MacOS
1. Open a terminal.
2. Run with sudo (required for service control and power management):
   ```bash
   sudo python3 main.py
   ```
   * Ensure the terminal has "Full Disk Access" if you encounter permission issues with logs or power management.

### Templates
Templates are pre-built configs stored under `data/template/win/` or `data/template/mac/`.  
They are selected with `--template` and copied over `data/config.json` before the test starts.

```cmd
# Run a single template (full or partial name)
python main.py --template=win/stress02
python main.py --template=win/stress02-traffic-flood

# Run multiple templates in sequence (comma-separated)
python main.py --template=win/stress02,win/stress03

# Interactive picker — lists all available templates
python main.py --template
```

Each run produces its own timestamped log folder, e.g. `log/20260313-142530-stress02`.  
Partial names (e.g. `stress02`) are resolved by prefix match against the JSON filenames.

## Reuse Power API from another repo

You can call the exported power APIs directly:

```python
from tool.power_api import enter_s0_and_wake, enter_s1_and_wake

ok_s0 = enter_s0_and_wake(30)
ok_s1 = enter_s1_and_wake(30)
```

If your caller already has a power manager instance, pass it in:

```python
from tool.power_api import enter_s0_and_wake

ok = enter_s0_and_wake(30, power_manager=my_power_manager)
```

For cross-repo use, install this project as a dependency or add it to `PYTHONPATH`.




## Features done

1. Config changes for FailClose
2. Crash dump monitoring and collection
3. **Service Hang Detection**: Auto-detects if service fails to stop, generates a Live Dump, and collects logs.
4. Estimate SYSTEM memory and CPU resource
5. Collect ~12,000 URLs and pick them randomly to use
6. More network traffic type generated by CURL and Python.
7. **Traffic Generation**: Dynamic creating browser tabs based on memory usage.
8. **Traffic Generation**: Massive traffic generation (DNS, UDP, FTP, FTPS, SFTP).
9. **Traffic Generation**: High-volume HTTP/HTTPS flood support (via Curl).
10. **Traffic Generation**: High concurrency connection testing (via Apache Bench).
11. **Simulation**: Block host to simulate FailClose.
12. **Simulation**: Network (NIC) enabling/disabling.
13. **Simulation**: System Sleep (S0) simulation.
14. **Simulation**: Client Enable/Disable toggling via `nsdiag`.
15. **Diagnostics**: Auto-collect log bundle (`nsdiag`) and dump files upon crash detection.
16. **Simulation**: TLS/DTLS tunnel protocol toggling via WebUI API.
17. **Simulation**: Steering mode (web/all) toggling via WebUI API.
18. **Simulation**: FailClose toggling via WebUI API (tenant-level).
19. **Simulation**: SNI check toggling via WebUI API.
20. **Simulation**: Exception domains add/remove toggling via WebUI API.
21. **Simulation**: Client disabling (`allowClientDisabling`) toggling via WebUI API.
22. **Simulation**: Custom steered ports add/remove toggling via WebUI API.
23. **Simulation**: Interop proxy enable/disable toggling via WebUI API.
24. **Simulation**: MTU value cycling via WebUI API.
25. Reboot and task scheduler to restart the tool
26. Steering mode changes
27. Dynamic Steering changes
28. Periodically stAgentSvc resource check
